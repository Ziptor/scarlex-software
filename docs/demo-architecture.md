# Как устроено демо Scarlex

Этот документ описывает только локальный пример, который запускается командой `npm start`.

- `ui/` показывает экран входа и состояние сессии. Для привязки используется фиксированный демонстрационный идентификатор, а не параметры компьютера.
- `server.mjs` раздаёт интерфейс и принимает JSON-запросы по адресу `127.0.0.1:4300`.
- `licenses.mjs` хранит хеш тестового ключа, срок действия и привязку в SQLite в памяти. Подписывающая пара Ed25519 создаётся при запуске и не сохраняется на диск.
- `rendering/` — отдельные фрагменты графического кода. Сервер демо их не загружает.

## Запросы

| Запрос | Результат |
| --- | --- |
| `GET /api/health` | Статус локального сервера. |
| `POST /api/auth` | Проверка тестового ключа и идентификатора устройства; выпуск билета при успехе. |
| `POST /api/refresh` | Проверка подписи, привязки и срока действия; выпуск нового билета при успехе. |

## Проверка

Команда `npm test` запускает тесты из `tests/`. Они проверяют успешную активацию, ошибочный ключ, попытку входа с другого тестового устройства, продление билета, подменённую подпись и истечение срока действия.
