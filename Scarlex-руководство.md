# Scarlex для Rob Run — руководство пользователя

Для лаунчера **1.2.4** и приложения **1.2.3**.

Scarlex состоит из лаунчера `scarlex_loader.exe` на WebView2, отдельного приложения с оверлеем DirectX 11 и драйвера WmPort. Лаунчер проверяет лицензию на сервере, скачивает и проверяет пакеты приложения и зависимостей, проверяет окружение и ждёт процесс игры. Затем он запускает приложение, которое открывает WmPort и инициализирует оверлей. Файлы `kd2.exe` и `kernel-mode.sys` поставляются в составе пакета зависимостей.

## 1. Проверьте компьютер

| Компонент | Требование |
| --- | --- |
| Windows | Windows 10 x64 версии 2004 или новее либо Windows 11 x64. Используйте физический ПК. Windows Server и виртуальные машины не входят в поддерживаемые конфигурации. |
| Процессор и память | Процессор x64 и от 8 ГБ оперативной памяти. |
| Графика | Видеокарта и установленный драйвер с поддержкой DirectX 11. |
| WebView2 | Установленный Microsoft Edge WebView2 Evergreen Runtime. Обычно уже есть в Windows 11 и на обновлённых установках Windows 10. |
| Права | Возможность повысить права лаунчера через UAC. Используйте ту же учётную запись Windows для игры и лаунчера. Права администратора для самой игры нужны, если их запрашивает её официальный клиент. |
| Сеть | Доступ к `scarlex.duckdns.org` по HTTPS для авторизации, загрузки и установки обновлений. |

1. Нажмите `Win + R`, введите `winver` и проверьте версию Windows. Разрядность указана в **Параметры → Система → О системе → Тип системы**.
2. Откройте `dxdiag` через `Win + R`. На вкладке **Экран** проверьте **Уровни функций**. В списке должен быть `11_0` или выше. Строка **Версия DirectX** на вкладке **Система** показывает версию среды Windows и сама по себе не подтверждает возможности видеокарты.
3. Найдите **Microsoft Edge WebView2 Runtime** в **Параметры → Приложения → Установленные приложения** (Windows 11) или **Приложения и возможности** (Windows 10). Если среды нет или лаунчер не может её открыть, скачайте **Evergreen Standalone Installer → x64** с сайта Microsoft, запустите установщик и снова откройте лаунчер. [Загрузка WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/#download)

Для повседневного использования предпочтительна поддерживаемая версия Windows 11. Обычная поддержка Windows 10 завершилась 14 октября 2025 года. Доступность обновлений для Windows 10 зависит от редакции и участия в ESU. [Срок поддержки Windows 10](https://support.microsoft.com/en-gb/windows/deployment/updates-lifecycle/windows-10-support-has-ended-on-october-14-2025?nochrome=true)

## 2. Проверьте настройки Windows

Начните с текущих настроек защиты. В релизе 1.2.4 **Windows Defender**, **VBS** и **HVCI** отображаются в панели состояния ПК. `UNKNOWN` или «НЕТ ДАННЫХ» означает, что лаунчер не смог подтвердить состояние. Для обращения в поддержку важны фактическая ошибка запуска и записи в журнале.

### Microsoft Defender

1. Откройте **Пуск → Безопасность Windows → Защита от вирусов и угроз**.
2. В **Журнале защиты** найдите событие на время запуска. Запишите имя файла, название обнаружения и действие Defender.
3. В **Параметры защиты от вирусов и других угроз → Управление настройками** находится переключатель **Защита в реальном времени**. Оставьте его включённым для обычного запуска.
4. В том же разделе **Исключения → Добавление или удаление исключений** проверьте существующие записи. Для установки Scarlex не добавляйте заранее папку лаунчера, `%LOCALAPPDATA%\Scarlex` или каталог игры в исключения. Если Defender заблокировал файл, передайте запись в поддержку Scarlex для проверки конкретной сборки. Исключение папки распространяется и на другие файлы, которые позже в ней появятся. [Настройки и исключения Defender](https://support.microsoft.com/en-us/windows/security/threat-malware-protection/virus-and-threat-protection-in-the-windows-security-app)

### Целостность памяти и VBS

1. Откройте **Безопасность Windows → Безопасность устройства → Сведения об изоляции ядра → Целостность памяти**. Запишите состояние переключателя. Это настройка HVCI.
2. Нажмите `Win + R`, введите `msinfo32`. В **Сведениях о системе** проверьте строку **Безопасность на основе виртуализации**. VBS может продолжать работать при выключенной целостности памяти.
3. При ошибке драйвера откройте `eventvwr.msc` и перейдите в **Журналы приложений и служб → Microsoft → Windows → CodeIntegrity → Operational**. Найдите событие на время запуска. Сохраните его код и имя файла. Если Windows сообщает о несовместимости, нужна совместимая сборка драйвера. На управляемом ПК параметры VBS может задавать организация. [Как проверить целостность памяти и VBS](https://learn.microsoft.com/en-us/windows/security/hardware-security/enable-virtualization-based-protection-of-code-integrity)

### Secure Boot, тестовый режим и UAC

1. В `msinfo32` проверьте **Режим BIOS** и **Состояние безопасной загрузки**. Для обычного запуска оставьте Secure Boot в текущем состоянии.
2. В командной строке с правами администратора выполните `bcdedit /enum {current}` для проверки параметров текущей загрузки. `testsigning Yes` означает, что для этой записи настроен тестовый режим. Команда ничего не меняет.
3. Параметр `bcdedit /set testsigning on` предназначен для стендов с тестово подписанными драйверами. Он требует перезагрузки. Для полностью неподписанного `.sys` он не заменяет подпись. Secure Boot может запретить изменение параметра. Для релиза Scarlex отключение Secure Boot и включение тестового режима не подтверждены как способ исправить загрузку WmPort. При блокировке драйвера передайте событие CodeIntegrity в поддержку. [Что делает TESTSIGNING](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/the-testsigning-boot-configuration-option)
4. Если по другой причине вам нужно войти в UEFI, используйте **Параметры → Система → Восстановление → Расширенные параметры запуска → Перезагрузить сейчас** в Windows 11. В Windows 10 начните с **Параметры → Обновление и безопасность → Восстановление**. В меню восстановления выберите **Поиск и устранение неисправностей → Дополнительные параметры → Параметры встроенного ПО UEFI**. Точное расположение Secure Boot зависит от модели ПК. Изменения параметров загрузки могут потребовать ключ восстановления BitLocker. [Вход в UEFI и настройка Secure Boot](https://support.microsoft.com/en-us/windows/security/secure-boot-enablement-guide)
5. Оставьте UAC включённым. Релизный лаунчер сам запрашивает повышение прав. При необходимости нажмите правой кнопкой мыши по `scarlex_loader.exe` и выберите **Запуск от имени администратора**. Подтвердите запрос для полученного от поддержки файла.

## 3. Устраните конфликты окружения

### Отладчики и сторонние античиты

1. Закройте активные сеансы x64dbg, IDA и Cheat Engine перед запуском. Если Process Hacker или другой инструмент инспекции подключён к Scarlex или игре, сначала завершите сеанс инспекции и закройте программу. Само наличие этих приложений на диске не означает, что к лаунчеру подключён отладчик.
2. Если Scarlex сообщает **«Запуск заблокирован: активен античит»**, запишите имя из сообщения. Среди распознаваемых компонентов есть FACEIT AC, Riot Vanguard (`vgc.exe`, `vgk.sys`), BattlEye (`BEService.exe`), ESEA, ESL Wire и EAC. Лаунчер может обнаружить службу или драйвер даже после закрытия окна клиента.
3. Закройте другие игры и их клиенты штатным способом. Если для стороннего античита предусмотрена команда **Выход** в области уведомлений, используйте её и примените указания клиента о перезагрузке. Повторно откройте Scarlex и проверьте сообщение. Если античит нужен другим играм, его удаление затронет и их. Если он больше не используется, удаляйте его только штатным деинсталлятором производителя.

### Easy Anti-Cheat в Rob Run

Лаунчер блокирует запуск, если при проверке распознал активный компонент EAC. Для этой версии Scarlex **работа с активным EAC не подтверждена**. Завершение `EasyAntiCheat.exe` в диспетчере задач не подтверждает отключение службы и не является проверенным способом запуска Rob Run с оверлеем. Лаунчер Scarlex сам не запускает игру в специальном режиме.

Если издатель Rob Run предоставляет официальный режим без EAC, используйте его только там, где разрешён сторонний оверлей. Если доступный режим требует EAC и лаунчер сообщает о конфликте, остановитесь на этом шаге и передайте точное сообщение в поддержку. Подтверждённого сценария для этого режима в руководстве нет.

## 4. Запустите Scarlex

1. Получите `scarlex_loader.exe` из канала распространения Scarlex. Сохраните его в отдельной папке, например `Документы\Scarlex`. При наличии контрольной суммы сравните SHA-256 перед запуском.
2. Откройте лаунчер и подтвердите запрос UAC. При необходимости выберите **RU** в интерфейсе.
3. Введите лицензионный ключ и нажмите **Войти**. Дождитесь авторизации и завершения загрузки. По умолчанию лаунчер устанавливает пакеты под `%LOCALAPPDATA%\Scarlex`. Открывайте приложение через лаунчер, чтобы оно получило данные текущей сессии.
4. В карточке Rob Run нажмите **Запустить**. Дождитесь проверки окружения. При сообщении о конфликте вернитесь к разделу 3.
5. После статуса **ОЖИДАНИЕ ИГРЫ** откройте Rob Run через официальный клиент и дождитесь появления окна игры. Если игра уже запущена в разрешённой конфигурации, лаунчер должен распознать её без повторного запуска.
6. Наблюдайте за строкой состояния запуска. **ЗАПУСК…** означает, что Scarlex выполняет инициализацию. **ПОДКЛЮЧЕНО** в статусе запуска означает, что приложение сообщило о готовности оверлея. Для первой проверки можно переключить игру в оконный или безрамочный режим.

## 5. Если запуск не удался

| Симптом | Что проверить |
| --- | --- |
| Лаунчер не открывается или окно пустое | Закройте сеанс отладки, проверьте установку WebView2 и наличие ошибки `boot` или `ui` в журнале. |
| «Сервер недоступен» | Проверьте соединение и дату, время и часовой пояс Windows. Откройте `https://scarlex.duckdns.org` в браузере. При ошибке сертификата сохраните её текст. |
| Ключ неверен, истёк или привязан к другому ПК | Перепроверьте ввод. Если ключ истёк или привязан к другому ПК, обратитесь к выдавшему лицензию. |
| «Не удалось установить обновление» | Проверьте свободное место на системном диске, запись `install/failed` и журнал защиты. Повторите вход через лаунчер, когда сеть доступна. |
| «ОЖИДАНИЕ ИГРЫ» не меняется | Убедитесь, что появилось само окно Rob Run. На вкладке **Подробности** в диспетчере задач проверьте наличие `ROB RUN.exe` или `RobRun.exe`. Если игра завершилась или показала ошибку EAC, сообщите об этом отдельно. |
| «Запуск заблокирован» | Запишите имя античита из сообщения. Сверьтесь с разделом 3. |
| «Драйвер недоступен» | Запишите исходный код ошибки и найдите событие CodeIntegrity на то же время. Откройте `app.log` и проверьте запись `payload_driver/open_failed`. |
| «Приложение ещё запускается» | Уточните в журнале, была ли запись `driver/ready` и появилась ли `overlay/ready`. Если запуск не продолжается, сохраните `loader.log` и `app.log`. |
| Оверлей исчез или не отрисовался | Проверьте `payload_overlay/graphics_failed` и `process/exited`, если они есть. Запишите код, режим окна игры и модель GPU. |

### Соберите данные для поддержки

1. Нажмите `Win + R`, вставьте `%LOCALAPPDATA%\Scarlex\logs` и нажмите Enter.
2. Сохраните `loader.log` и `app.log`, если он появился. Первый показывает работу лаунчера, второй помогает определить этап сбоя дочернего приложения.
3. Укажите версию лаунчера, время ошибки с часовым поясом, сборку Windows из `winver`, сообщение интерфейса и последние события запуска. При наличии добавьте код Win32/HRESULT, код завершения и ID сессии из `loader.log`. Лицензионный ключ и пароли в обращение не вставляйте.
4. После авторизации лаунчер отправляет диагностические события по сети. Поддержка может сверить их с журналом лицензии. При ошибке до авторизации или при недоступной сети приложите локальные журналы.
