# Иконки оружия

## Что добавлено

- `TextureManager.h/.cpp`: загрузка PNG через существующий Windows Imaging Component, преобразование в RGBA8 и создание `ID3D11ShaderResourceView` на D3D11-устройстве оверлея. Дополнительные зависимости не нужны.
- `LoadTexture(const std::string&)` принимает UTF-8 путь. Относительный путь разрешается от папки EXE. Успешные загрузки и ошибки кэшируются; PNG не декодируется заново каждый кадр. Нормализованные пути с разным регистром ASCII используют один кэш. Ошибка PNG сообщает HRESULT один раз для этого пути.
- `WeaponIcon` принимает сырой ID, применяет существующую нормализацию и проверенные алиасы имён файлов. ID со слешами и обходом каталогов не допускаются.
- `IconSize` вписывает исходное изображение в область `width × width/2`, сохраняя пропорции. Ширина ограничена 16–64 px. Большие исходные PNG уменьшаются при загрузке до 512 px по большей стороне; прозрачность сохраняется.
- Менеджер принадлежит `OverlayD3D11::State`. Загрузка и использование происходят в потоке рендера. При завершении оверлей освобождает ImGui, снимает привязки D3D11-контекста и уничтожает менеджер. Деструктор менеджера вызывает Release для каждого принадлежащего ему SRV. Возвращённые ID действительны до `Clear` или уничтожения менеджера.

## Настройки меню

- **ESP → Held weapon → Weapon Display**: `Text`, `Icon`, `Both`. Поле профиля: `esp.esp_weapon_display_mode` со значениями 0, 1, 2. Для старого профиля по умолчанию сохраняется Text.
- **Indicators → Show weapon icon on arrows**: поле `indicators.arrow_show_weapon_icon`, по умолчанию true. Иконка рисуется без поворота снаружи вершины стрелки, с отступом и ограничением по краям экрана. При открытом меню скрывается вместе со стрелками.
- **Settings → Weapon icon size**: общая ширина 16–64 px, по умолчанию 48, поле `weapon_icon_size`. Все параметры сохраняются и загружаются через существующий JSON-профиль.

В ESP иконка размещается под боксом, после роли. Both добавляет под ней текущее название, доступные патроны и существующую строку редкости/цены. Icon скрывает эти текстовые строки при наличии PNG. Если иконка отсутствует, остаётся доступное название. При отсутствии и PNG, и известного названия подпись остаётся скрытой по прежней политике неизвестных ID. Подтверждённое `Unarmed` сохраняет отдельную настройку.

Используется `GetBackgroundDrawList()->AddImage`: модули рисуют вне `ImGui::Begin`, поэтому им не нужен активный ImGui-window. Меню остаётся поверх этих элементов.

## Проверенные несовпадения ID

Десять PNG используют другой ID, чем прежний weapons.csv. Соответствия установлены по точному совпадению названия оружия в предоставленном weapons.json и прежнем CSV. В `game_data.h` добавлены runtime-ID → CSV-ID, а `TextureManager` использует обратное соответствие для имени PNG:

| CSV ID | Имя PNG без расширения |
|---|---|
| `m249_m2` | `lmg_m2` |
| `weapon_drm14_mk2` | `drm14_m2` |
| `weapon_drm14_mk3` | `drm14_m3` |
| `tag12_m1` | `tag12k_m1` |
| `weapon_tag12_mk2` | `tag12k_m2` |
| `weapon_tag12_mk3` | `tag12k_m3` |
| `vulture_m1` | `vulture50_m1` |
| `vulture_m2` | `vulture50_m2` |
| `weapon_lbr44_mk2` | `lbr44_m2` |
| `weapon_dp9_mk2` | `dp9_m2` |

Оба варианта ID дают одну закэшированную текстуру. Для остальных файлов исходные ID совпадают.

## Проверка

MSVC C++20 Release x64 собран без нового предупреждения о deprecated API. Проверка с `/W4 /WX` завершилась `PASS: 58 icon/config/render checks`: все 46 PNG, повторные загрузки, регистр пути, нормализация и алиасы, отрицательный кэш, пропорции, размер, три режима ESP, переключатель иконок стрелок, скрытие при меню, совместимость профиля и очистка кэша. Отдельная проверка существующих функций завершилась `PASS: 641 checks including fixture bounds`.

В настоящем `OverlayD3D11` на тестовом окне вне рабочего стола сформирован и представлен кадр D3D11; кадр прочитан с GPU в PNG и визуально проверен. Это проверка рендера на тестовых сущностях, а не подтверждение текущего оружия игроков в реальном матче.
