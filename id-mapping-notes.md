# Нормализация ID и CSV-каталоги

## Изменения

`game_data.h/.cpp` содержит `normalize_id`, `lookup`, статическую таблицу `overrides`, каталог предметов, оружия и точек карты. `game_data_entries.inl` сгенерирован из переданных UTF-8 файлов: 569 предметов, 46 оружий, 927 точек карты. Контрольные суммы исходных CSV записаны в начале соответствующих таблиц. Каталоги встроены в EXE; копировать CSV рядом с ним не нужно. Чтобы обновить строки каталога, нужно повторно сгенерировать `.inl` и пересобрать проект.

Порядок обработки:

1. Один начальный `event-` удаляется.
2. Удаляется до двух конечных групп `-<цифры>`; многозначные числа допускаются.
3. Оставшиеся дефисы заменяются подчёркиваниями.
4. Если очищенный ключ отсутствует во всех трёх каталогах, проверяется `overrides` по исходному, необработанному ID.
5. Полученный ключ проверяется по каталогам. Отсутствующие и пустые значения остаются неизвестными.

| Сырой ID | Итог | Найден | Использован override |
|---|---|---|---|
| `garbage1-1` | `garbage_1` | да | да |
| `garbage1-2` | `garbage_1` | да | да |
| `event-atm` | `atm` | да | нет, очищенный ключ уже существует |
| `event-safe` | `safe` | да | нет, очищенный ключ уже существует |
| `garbage1-3` | `garbage1` | нет | нет, такое правило не добавлено |
| `donor_159` | `donor_159` | да | нет |
| `159` | `159` | нет | нет, donor-ID не угадывается |

Расширять таблицу нужно в `game_data.h`:

```cpp
inline const std::unordered_map<std::string, std::string> overrides{
    {"garbage1-1", "garbage_1"},
    {"garbage1-2", "garbage_1"},
    {"event-atm", "atm"},
    {"event-safe", "safe"},
    // Add a verified raw ID -> actual CSV key here.
};
```

После изменения таблицы требуется пересборка. Это не набор правил автоматического вывода: отсутствующее соответствие не придумывается.

## Поведение на экране

`LootModule` выполняет поиск через общую нормализацию для родительского объекта и каждого предмета содержимого. Если ключ найден, используется русское название, затем английское. Редкость из CSV определяет цвет; при пустой редкости сохраняется цвет из прочитанных данных или категории. Оружие лута остаётся красным. Для доступных данных дополнительной строкой показываются редкость и диапазон цены в USD. Пустая цена остаётся неизвестной, а не превращается в ноль.

`ESPModule` разрешает `Entity.weapon_id` тем же способом, предпочитает название из таблицы оружия, сохраняет фактически прочитанные патроны и добавляет доступные редкость/цену. Ёмкость магазина из CSV не подменяет текущий остаток. При неизвестном ID подпись оружия скрывается; ESP самого игрока продолжает работать. Подтверждённое отсутствие оружия по-прежнему может отображаться как `Unarmed`.

При неизвестном ID лута не рисуются ни маркер, ни подпись `Unknown`. Это соответствует последнему пункту запроса о скрытии ненайденных объектов. Для известной точки `donor_*` подпись включает здание, если оно указано в каталоге.

Добавлена компиляция MSVC с `/utf-8`. Диапазон встроенного шрифта включает кириллицу и типографскую пунктуацию из CSV.
Для всех подписей оверлея явно выбран встроенный шрифт Inter, он также установлен как `FontDefault`. Это исправляет вопросительные знаки при корректном UTF-8. Дополнительная проверка шрифта и D3D11 завершилась `PASS: 33 font/render checks`.

## Журнал неизвестных ID

`unmatched-ids.jsonl` создаётся рядом с запущенным EXE при первом несовпадении и перезаписывается для новой сессии этого экземпляра программы. Каждый сырой ID записывается один раз, даже если встречается в потоке чтения, рендере и нескольких типах объектов. `context` хранит место первого обнаружения. Если файл открыть не удалось, остаются сообщения консоли.

```json
{"status":"unknown","raw_id":"garbage1-3","normalized_id":"garbage1","override_applied":false,"context":"loot-reader"}
```

Пустой ID записывается как `""`. Управляющие символы экранируются, UTF-8 сохраняется. Перед записью установлена блокировка; дубликаты не добавляются.

Узлы дополнительно получают поля `raw_id`, `normalized_id`, `matched`, `override` в строке `[LOOT-NODE]`. `runtime_id` в этой строке — целочисленный ключ реестра, `raw_id` — исходный строковый ID описания. Эти значения не смешиваются.

Важное ограничение: `atm` и `safe` найдены в каталоге предметов и дают общие названия. Это не устанавливает конкретную точку `donor_*`, её здание или район. В предыдущем снимке строковый ID `0` встречался у разных узлов; глобальное правило `"0" → "donor_…"` ошибочно присвоит одно место всем таким узлам. Для повторяющихся ID нужна отдельная привязка к координатам/экземпляру.
